# FGMP/1：FieldGate 农机描述协议

作者：刘泽禹。版本：1，2026-09-09。

## 目标与边界

算力模块继续使用用户提供的三合一 CAN 协议。FGMP 是配置描述协议，不是替换三合一的控制协议。
同一个通用运行核心加载不同的数据表，对已实现能力进行组合，无须为每个农机型号复制一份 C 程序。
原版三合一走校验后的双向原样转发；其他执行器走明确的信号映射和已实现运动转换。

描述采用公开的 [JSON Schema Draft-07](https://json-schema.org/draft-07)；Schema 位于 `profiles/fgmp-v1.schema.json`。
选择该版本是为了直接复用项目已有的离线 Ajv 依赖。格式验证之外还有拓扑、信号单位和安全语义检查。
DBC 是三合一线格式的依据，不替代设备分类、结构参数、接口绑定或安全配置。

本版已实现：描述文件、严格校验、确定性二进制编译/读回、三种示例、离线模拟、可移植 C 加载/映射/转发核心及主机测试。
`fgmp_profile.c` 已加入 HPM 工程，但**尚未接管板端主循环，未增加板端配置上传/CRUD，也没有烧录或实机验证**。
此前 FGCP 运行代码为旧兼容路径，未删除；本版 FGMP 核心的上游只接受三合一，不会把 FGCP 当作默认输入。

## 顶层类目

| 类目 | 用途 | 关键规则 |
|---|---|---|
| `identity` | UUID、版本、名称、制造商、作者、调试完成标记 | 原始注册 ID 作为兼容信息保留；新增身份不靠修改固件枚举 |
| `machine` | 行走结构、输入解释、几何与标定 | 百分比与速度绝不混用 |
| `upstream` | 算力协议、物理总线、速率 | v1 固定三合一 CAN1；默认示例 250 kbit/s |
| `downstream` | 执行器物理总线、速率 | v1 使用独立 CAN0；两侧不可在同一物理总线上回环 |
| `safety` | 新鲜度、重新使能、必要反馈 | 必须真实反馈、外部许可和中立指令，不能由界面勾选替代 |
| `routing` | 透传白名单或有界输出映射表 | 不自动广播未知 ID，不动态执行脚本 |
| `devices` | 驱动、转向、灯、作业设备、电池等清单 | 控制状态与实际反馈分开，供界面与部件绑定使用 |
| `extensions` | 带命名空间的非运行元数据 | 可放来源、模型部件映射；不能暗中增加执行能力 |

现有模板：

- `profiles/three-in-one-original.json`：原版履带差速农机、三合一 CAN 协议，保留机型 0x0001／协议 0x0101。
- `profiles/ackermann-four-lights.example.json`：阿克曼及四路联动灯光，几何参数和灯光报文均为离线示例。
- `profiles/differential-work.example.json`：差速运动加风机、水泵、碎枝机映射示例。

三个文件默认 `commissioned=false`，C 核心即使获得软件许可也不发送执行器指令。
该标记只记录调试状态，不是认证或权限系统；不能通过把它改成 true 来代替实际调试。

## 三合一输入，不更改旧报文

| 报文 | 读取内容 | 实际含义 |
|---|---|---|
| 0x514 | Byte1/2 有符号 8 位、Byte3 bit0 | 左右驱动百分比、总照明开关 |
| 0x580 | Byte0 低/高半字节、Byte1/2 小端 | 风机档位、水泵档位、碎枝输出百分比×100 |

长度均为 8，Byte6 低四位为循环计数，Byte7 为 Byte0～6 异或。
本版运行策略限制驱动 ±100%、档位 0～8、碎枝 0～10000；这是明确的应用安全范围，不是重写 DBC 的位宽。
循环计数允许前进 1～8，重复及明显倒序拒绝；超时后只接受中立控制重新同步。
必要反馈也校验循环计数，重复反馈不能刷新安全时间。

原报文没有独立四灯指令，也没有完整的通用急停命令。四路灯可映射到不同输出位，但都跟随 `lighting.headlight`。
未来若需要独立灯光，必须以明确版本扩展上游，不能偷用保留位后仍宣称完全兼容旧协议。

## 通用控制源与运动转换

控制源固定编号 0～9：

`drive.leftPercent`、`drive.rightPercent`、`lighting.headlight`、`work.fanGear`、`work.pumpGear`、`work.shredderX100`、`drive.forwardMmS`、`drive.yawMradS`、`drive.leftSteeringMrad`、`drive.rightSteeringMrad`。

`native_percent`：不生成速度和转角。`calibrated_virtual_differential`：必须显式给出参数，约定左右百分比对应虚拟左右轮速度：

```
vL = leftPercent × wheelSpeedAt100PercentMmS / 100
vR = rightPercent × wheelSpeedAt100PercentMmS / 100
v  = (vL + vR) / 2                         [mm/s]
w  = (vR - vL) / trackMm                   [rad/s]
```

这是一种需要算力侧认可、需要实机标定的兼容解释，不是说 PWM 天然与实际轮速线性对应。
轮距也定义了输入虚拟差速模型；如果算力程序此前以另一轮距计算左右量，两端参数必须对齐。

阿克曼使用曲率 `k=w/v`，再计算左右实际前轮转角。限制曲率使内侧轮不超过最大转角，外侧轮保持几何关系，不是独立截断两个角度。
倒车保留正确符号。低速非零旋转请求拒绝，不能把阿克曼当成可以原地差速旋转的结构。
当前转向协议第三字段使用左前轮转角，不与角速度混用。转向速度限制与制动策略须在实际执行器系统中落实后才可启用。

## 固定 CAN 映射

每条输出报文包含：ID、行走/作业域、8 字节底值、可选计数与校验、最多 8 个字段。
最多 16 条报文。字段长度 1～16 位，支持小端任意起始位和整字节对齐大端 8/16 位。
`big_byte_aligned` 的起始位是字节偏移×8，**不是 DBC Motorola sawtooth 位编号**。

```
wireRaw = trunc(source × numerator / denominator) + offset
```

字段范围越界整条请求拒绝，不截断回绕。每字段显式给出 `safeRaw`，可表达反相开关的安全电平。
同一报文只允许绑定同一更新域，防止把一条新行走指令和过期作业数据混合发送。
字段、计数器、校验位不能重叠；输出 ID 不能重复或与反馈 ID 冲突。
映射报文以 100ms 周期输出，超时后写安全值；不支持特殊握手、CANopen SDO 状态机、J1939 多包、任意校验脚本等未实现能力。
这些能力以后以新版本、已测试适配器扩展，而不是在 JSON 中嵌入 C/JavaScript。

`0x181` 示例沿用已有运动/转向报文；`0x210` 灯光和 `0x212` 作业报文只是描述能力的自定义示例，不能假定任何品牌执行器都会接受。

## 反馈与安全

v1 反馈是配置白名单内三合一原始反馈的原样转发，不合成正常状态。
必须有真实 0x532，且其工作模式为自动、急停未触发，并满足全部必要反馈新鲜度，才允许通过中立指令进入运行。
异构驱动器若没有三合一安全反馈，必须先新增真实状态转换适配；不能向算力伪造健康帧来绕过限制。

`fgmp_engine_set_permit` 是硬件集成方提供的额外运行许可入口，默认关闭；它不能代替独立的急停和安全输出电路。
关闭许可、失联、错误控制、发送失败均撤销中立确认。恢复健康或通信本身不会自动恢复非零指令。

透传模式不重播过期控制、不修改原报文字节。失去许可后停止转发，依赖原执行器自身的超时停车；这不是瞬时切断功率。
映射模式使用配置的安全值，外部硬件仍须保证急停和输出禁止。两者都不构成功能安全认证。

## FGMP 二进制包

小端有界格式；不是把 C 结构体直接写 Flash，避免编译器填充差异。
总长度最大 16384 字节，包含执行表和完整 UTF-8 JSON。名称、作者、设备类目和扩展信息可完整导出。

| 偏移 | 内容 |
|---|---|
| 0 / 4 / 6 | `FGMP`、u16 版本 1、u16 头长 128 |
| 8 / 12 | u32 总长、u32 CRC32（覆盖 Byte16 到包末尾） |
| 16 / 32 | UUID 16 字节、u32 配置修订号 |
| 36～39 | 结构、路由模式、调试完成、中立确认标记 |
| 40 / 44 | 两侧 CAN 位速率 |
| 48～61 | u16 超时、轮距、轴距、最大轮速、最大转角、低速阈值 |
| 62～65 | 输入模型、报文数、反馈数、必要反馈数 |
| 68 / 100 | 最多 16 个反馈 ID、最多 8 个必要反馈 ID |
| 116 / 120 | 原始 JSON 长度及起始偏移 |
| 128 起 | 每报文 176 字节，16 字节报文头＋8×20 字节字段记录 |
| 执行表末尾 | 规范化完整 JSON；不含日期随机数，内容相同输出相同 |

报文头：u16 ID、u8 域、u8 计数方式、u8 校验方式、u8 字段数、保留 2 字节、底值 8 字节。
字段：u8 控制源、u8 起始位、u8 长度、u8 标记（bit0 有符号，bit1 大端），i32 分子、u32 分母、i32 偏移、i32 安全值。
保留及未使用记录必须为零。未知版本、超限、重叠、错误 CRC 一律拒绝。

C 端执行经检查的二进制表，不运行 JSON 解释器。上位机读回时重新编译 JSON 并逐字节比对，避免源描述与执行表不一致。
CRC 只检测损坏，不提供来源认证。生产配置发布、身份校验和签名需在部署层补充。

## 工具与验证

在 `host_app` 中：

```powershell
node scripts/profile-tool.mjs validate ../profiles/ackermann-four-lights.example.json
node scripts/profile-tool.mjs compile ../profiles/ackermann-four-lights.example.json C:/hpm_analysis/ackermann-v1.fgmp
node scripts/profile-tool.mjs inspect C:/hpm_analysis/ackermann-v1.fgmp
node scripts/profile-tool.mjs simulate ../profiles/ackermann-four-lights.example.json 0x514:0032320100000100
node --test tests/machine-profile.test.mjs
& ../firmware/vcu_configurator/tests/run_host_tests.ps1
```

工具只生成新文件，拒绝覆盖已有文件。`compile ... --deployment` 额外要求调试完成；示例默认拒绝。
`simulate` 是无串口、无 CAN 访问的静态信号预览，绕过的是物理测试环境而不是任何实机安全许可。
主机 C 测试使用单一可执行文件依次加载三个临时测试包；调试标记仅在临时合成测试数据中开启，原始模板不修改。

## 下一步板端配置管理接口

配置与固件要分别管理。板端管理接口应提供能力查询、列表、读回、暂存上传、提交、删除、激活；UUID＋revision 定位配置。
更新提交与当前运行配置分开报告，启用必须在维护状态并重启核验。固件不支持的描述能力应明确拒绝。
现有 24 字节 VCFG/1 写选择接口保留，不用它强塞完整配置包。
16KiB 包的双份存储需要重新划分并保护 Flash 区域，不能覆盖旧选择记录所在末两扇区。
这些传输、持久化和主循环接入属于下一阶段，当前代码没有虚构板端 CRUD 成功。
