## 线上协议

### 串口指令

115200、8N1，固定 11 字节。参考 `uartx_callback.c:26` 起的接收回调及 `system.c` 初始化。

| 偏移 | 内容 |
| --- | --- |
| 0 | `7B` |
| 1 | 模式；本实现固定 0（正常运动） |
| 2 | 保留，本实现固定 0 |
| 3–4 | 前向速度，signed int16，大端，mm/s |
| 5–6 | 横向速度，signed int16，大端，mm/s |
| 7–8 | 偏航角速度，signed int16，大端，mrad/s |
| 9 | 字节 0–8 的 XOR |
| 10 | `7D` |

固定样本：前向 1m/s、横向 -0.5m/s、偏航 0.25rad/s 对应 `7B 00 00 03 E8 FE 0C 00 FA 98 7D`。这是离线测试数据，不是建议的上电指令。

模式 1/2（充电导航）、3（红外接近）及 FF（网络参数）不纳入常规运动 API，避免误触发。原程序 FF 有效帧也会清零指令丢失计数，不能用它维持运动看门狗。

### CAN 指令

标准数据帧 `0x181`，DLC=8，前六字节分别为三组大端 signed int16，末两字节填 0。参考 `can_callback.c:27`。

物理速率为 **1Mbps**：`system.c` 调用 `CAN1_Mode_Init(1,3,3,6,0)`，配合 42MHz 外设时钟，计算为 `42MHz / (6 × (1+3+3))`。源码附近存在旧注释，不能据旧算式配置。既有履带协议仍为 250kbps，不可把两类设备直接放在同一速率总线上。

**转向语义有差异**：串口在转向车型中调用 `Akm_Vz_to_Angle`（`balance_task.c:732`），把速度和角速度转换为左前轮角度；CAN 路径没有这次转换，第三字段直接作为左前轮角度，单位 mrad。因此提供单独 `encodeSteeringCanMotion` / `hechuan_encode_steering_can`，不能原样转发串口的 yawRate。若以后从统一角速度接口转换，必须取得实物轮距、轴距及转角限制；本次没有猜测这些参数。

### 运动反馈

参考 `data_task.c`：20Hz，串口每帧 24 字节。

| 偏移 | 内容 |
| --- | --- |
| 0 | `7B` |
| 1 | 驱动禁用标志（0/1），不是硬件急停状态 |
| 2–7 | 前向、横向、偏航，三组大端 signed int16，比例 1000 |
| 8–13 | 三轴加速度原始值，三组 signed int16 |
| 14–19 | 三轴陀螺仪原始值，三组 signed int16 |
| 20–21 | 电压 mV，原实现为 signed int16，不擅自扩为无符号 |
| 22 | 字节 0–21 的 XOR |
| 23 | `7D` |

CAN 将同一帧按 8 字节拆成 `0x101 → 0x102 → 0x103`。新增接收器要求顺序、标准数据帧、DLC=8、总耗时不超过 100ms 并校验整帧；100ms 是本接收器的过期策略，不是原协议中的时间戳。该协议没有序号，仍无法绝对排除丢帧后的跨周期拼接，应在控制系统层处理数据新鲜度。

IMU 保留线上坐标及原始量，不杜撰 SI 比例。源程序打包为 y、-x、z；驱动禁用时可能将 gyro.z 清零。超声和充电反馈使用其他帧，不作为运动反馈解码。

## 新命名与配置注册

| 农机 | machine_id | protocol_id | 总线速率 |
| --- | --- | --- | --- |
| 禾川履带农机（原有协议） | 0001 | 0101 | 250kbps |
| 禾川差速农机 | 0010 | 0201 | 1Mbps |
| 禾川四驱农机 | 0011 | 0201 | 1Mbps |
| 禾川转向农机 | 0012 | 0202 | 1Mbps |
| 禾川横移农机 | 0013 | 0201 | 1Mbps |
| 禾川全向农机 | 0014 | 0201 | 1Mbps |

表内 ID 均为十六进制。新 ID 是本项目注册表分配，不是供应商协议中的车型字段。控制板实际编译车型仍须与实物对应，仅保存这些 ID 不会改写外部控制板的车型固件。

保留原 `VCFG/1` 24 字节配置格式和既有 ID；上位机按型号自动选择协议。固件使用 `vcu_machine_profile.c` 校验组合，启动时也校验 Flash 读出的组合。bitrate 查询函数返回目标速率，但当前主循环尚未调用它初始化运行总线。

## 本次实现与未实现

已实现：JS/C 串口指令编解码、分离的 CAN 指令编码、反馈解码、JS 串口流重同步及 CAN 拼帧；六类配置在上位机及 HPM 固件中注册；模块纳入 HPM 构建；界面保存仍经真实 VCFG 回复校验。JS 运动模块供后续运行接入，配置页面不调用它发送运动。

**未实现/未验证**：FGCP 到这些运动帧的实机连续转发、CAN0 的运行初始化与收发调度、外部执行器安全联锁、几何参数标定、负载台架及本版本 Flash 烧录验证。C 运动模块已加入编译，但尚未由 `main.c` 的配置循环调用。不能将协议模块与配置写入等同于整机运动控制已经可用。

原 100Hz 控制循环在特定安全等级下约 1 秒指令丢失后才停止，并非始终启用的 500ms 停车。源码启动 10 秒后存在约 2 秒的 0.2m/s 自动运动段；**没有移植该段**。未来运行固件必须默认零输出，以经过验证的独立安全策略决定使能、超时停车和急停；上位机“已停稳”勾选框不能替代硬件联锁。

验证入口：`host_app` 下运行 `npm test`、`npm run lint`、`npm run typecheck`；固件便携测试运行 `tests/run_host_tests.ps1`（Windows）或 `.sh`。浏览器模拟串口仅用于交互与异常测试，不接实物。
