# 给文档作者与网页大模型的阅读指南

## 建议阅读顺序

1. 根目录 README 和 `09_resources_and_licenses.md`，先确认交付边界。
2. `01_overview.md`、`02_architecture.md`，建立组件和部署关系。
3. `11_code_map.md`，按路径进入源码，不凭历史聊天补写功能。
4. `04_unity_manual.md`、`05_console_manual.md`，分别编写两套应用的操作步骤。
5. `06_algorithms.md`、`07_interfaces.md`，说明算法接口与配置传递。
6. `10_validation.md`，区分接口可选、静态检查、实际运行、人工确认。

## 两份文档建议目录

设计说明：设计目标、运行环境、总体架构、模块设计、数据流、接口设计、持久化、异常处理、安全边界、验证与限制。

用户手册：准备条件、安装、界面与术语、选车装配、场景和算法、启动停止、经停点、导出配置、控制台导入、真机只读检查、导航、数据采集、AI 助手、故障排除。

## 术语

- “Unity 配置软件”：PC 上的三维车库、装配、算法选择、仿真启动和导出应用。
- “农机控制台”：ROS 网关、网页和 Android 外壳，用于真机状态、任务和采集。
- “仿真验证”：Gazebo 传感器输入下运行算法，不等于物理车辆标定通过。
- “导出真机配置”：生成结构和参数包，不代表已烧录底盘、写入传感器或自动完成安全验收。
- “默认算法”：取决于车辆和场景，不能在全文写成所有场景一律 FAST-LIVO2。

## 证据优先级

当前源码/JSON/YAML > 有配置指纹的运行记录 > 有范围限制的人工确认 > 历史 README > 宣传性描述。`manifests/source_snapshot.json` 记录来源版本和快照文件哈希；源码本身含当前未提交修改，所以不能只用原始 HEAD 概括本交付。

车辆、机具、场景不要在文档里维护第二份凭空扩展的清单。读取：

```text
unity/Assets/AgribotConfig/Resources/farm_vehicle_presets.json
ros2_ws/src/agribot_farm_sim/config/compatibility.json
ros2_ws/src/agribot_farm_sim/config/scenarios.json
ros2_ws/src/agribot_farm_sim/config/manual_validation_policy.json
ros2_ws/src/agribot_farm_sim/config/manual_confirmations*.json
```

## 不得扩大叙述

- 算法选项组合数不是独立原创算法数量，也不是全部组合已跑完全程。
- 同一车/场景的代表机具通过后，按用户规则确认其他适配机具，不等于逐一实测。
- AI 助手读取文字状态和场景目录，不直接理解当前相机画面或扫描点云。
- 导入场景名称不是场景语义、GNSS可用性或道路可通行性的自动识别结果。
- 仿真机具不参与当前碰撞/导航轮廓，所以不能声称验证了机具避障、作业动力学或真实耕作。
- 公开代码缺少的授权模型、SDK、设备和 API Key 必须写成安装前提，不得隐去。
- 当前包中包含历史对比算法，不等于真实车辆同时运行全部算法。
- 不编造独立第三方认证、定位厘米级保证、全组合可靠性或专利授权情况。

## 可用的撰写任务

可以给网页大模型以下任务：

> 阅读本仓库 README 和 docs/00 至 docs/11，以当前源码为依据编写软件设计说明与用户手册。明确区分 Unity 配置软件与农机控制台，写出各功能入口、输入输出、状态与失败处理。保留资源授权、真机标定、算法适配和验证范围的限制。引用相对源码路径，不把接口数量、历史人工确认或仿真结果改写为所有组合已实测。不补写仓库不存在的界面、截图、性能数据和硬件能力。
