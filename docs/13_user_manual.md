# 农机配置与算法仿真软件用户手册

适用对象：使用当前 Unity Linux 桌面软件完成选车、装配、算法仿真和配置导出的用户。

本手册只介绍 Unity 软件及 Gazebo/RViz，不包含手机控制台、网页控车、真实底盘或固件烧录。功能原理见[详细功能说明](12_detailed_functions.md)，当前目录见[车型与场景附录](14_catalog_reference.md)。

## 1. 首次使用前

### 1.1 准备条件

| 项目 | 要求/检查方法 |
| --- | --- |
| 操作系统 | 本交付基线 Ubuntu 22.04 amd64，图形桌面可用 |
| ROS | ROS 2 Humble，仿真依赖已构建 |
| 仿真器 | Gazebo Classic 11；RViz 和 Navigation 2 面板可加载 |
| Unity 程序 | 使用对应项目版本构建的 Linux App；开发构建用 Unity 6000.0.26f1 |
| 模型资源 | 所选车、机具、场景及预览/贴图完整，不是 Git LFS 指针 |
| AI | 可选，需本机凭据和可达的模型接口；手动流程不依赖 AI 成功 |
| 额外视觉 AI | 可选，需相应 Python 环境和权重 |

当前仓库部分完整车库资源仍未补传。已有 App 的功能描述不等于当前仓库已完成所有资源交付；从源码构建前先查看[资源说明](09_resources_and_licenses.md)，不要跳过预检或用空模型代替。

### 1.2 从仓库准备环境

```bash
git clone https://github.com/Guanzhen-C/agribot_report.git
cd agribot_report
git lfs install --local
git lfs pull
python3 tools/doctor.py
bash scripts/install_dependencies.sh
bash scripts/build_ros.sh simulation
```

上述依赖安装以已安装 ROS Humble Desktop 为前提。完整步骤和大模型文件下载恢复见[安装文档](03_installation.md)。

如需从源码构建完整 Unity App：

```bash
python3 tools/doctor.py --unity
export UNITY_EDITOR=/path/to/6000.0.26f1/Editor/Unity
bash scripts/build_unity.sh
```

只有完整预检通过后才继续构建。Unity 许可证和模型资源不足时，应先解决相应错误。

### 1.3 打开软件

```bash
cd /path/to/agribot_report
bash scripts/run_unity.sh
```

该脚本为本交付目录设置 ROS 路径并打开已构建程序。不需要启动手机服务或连接真实底盘。开发者从 Editor 运行时，应在加载 `scripts/env.sh` 的同一终端打开项目。

## 2. 界面与常用操作

### 2.1 页面关系

```text
车库 -> 单车配置
          -> 装备面板
          -> 爆炸图
          -> Car0 修理/参数面板
          -> 仿真实验室：作业场景 / 算法配置
          -> 启动 / 停止 / 配置导出

AI 助手可在同次运行中跨页面使用。
```

### 2.2 按钮说明

| 按钮/入口 | 用途 | 注意 |
| --- | --- | --- |
| 返回车库/BACK | 离开单车界面重新选车 | 不将返回页面当成停止仿真 |
| Open Bag/装备入口 | 打开传感器和农机具目录 | 不同车辆可安装范围不同 |
| 安装/卸下 | 改变选中装备状态 | 等待动画完成，不重复点击 |
| 爆炸图 | 展开已有零部件层级 | 不是编辑真实传感器位置 |
| 启动仿真 | 打开配置流程并提交启动 | 最终仍需选齐场景和算法 |
| 停止仿真 | 停止软件管理的仿真会话 | 等待成功提示再切换 |
| 导出真机配置 | 导出当前接口支持的配置/草案 | 不自动标定、烧录或控车 |
| AI 助手 | 对话及可点击方案 | 应用方案不等于启动 |

按钮文字或显示时机可能随车型及页面状态变化，应以当前界面为准。灰色按钮表示当前条件未满足，不要反复点击。

### 2.3 鼠标和输入

| 操作 | 方法 |
| --- | --- |
| 环绕车辆 | 在非 UI 区域按住鼠标左键拖动 |
| 拉近/拉远 | 鼠标滚轮 |
| 操作面板 | 指针移到按钮、输入框或滑条；相机不应同时响应 |
| Car0 修理面板 | 在单车界面双击车身，而不是双击 UI 或装备 |
| AI 发送 | 回车或“发送” |
| AI 换行 | Shift+回车 |
| 关闭面板 | 使用当前面板可见的关闭/返回按钮 |

不要把当前桌面程序当成 Android 版本。代码中的触控分支不代表已经交付移动端应用。

## 3. 选择农机

1. 在车库中查看车辆，必要时滚动找到其他车型。
2. 点击需要的车辆，进入对应单车配置界面。
3. 确认名称和模型，观察车体、车轮/履带以及准备安装的区域。
4. 选错时返回车库重新选择。

Car0～Car9 的准确名称、运动学和机具目录见[附录第1节](14_catalog_reference.md#1-车型与可挂载机具)。其中 Car3 和 Car9 为履带车型，Car8 当前为受控前轮转向的阿克曼配置，不能按旧差速版本理解。

模型看起来较小或较大，不代表可以直接用画面比例判断实际通行宽度。仿真参数使用米制配置，大农机仍需足够净空和转弯空间。

## 4. 安装传感器和农机具

### 4.1 基础传感器

1. 打开 Open Bag/装备面板。
2. 点击雷达装备，查看预览，点击安装并等待结束。
3. 按相同方式安装相机、IMU 和卫星定位组件。
4. 在车体上观察装备是否已出现，检查选中项是否切换为可卸下状态。
5. 使用面板关闭按钮回到车辆界面。

当前常规导出流程需要基础传感器装配完整。缺少某项时按提示安装，不用反复启动来绕过检查。

软件使用为车型预设的位置。不能通过拖动物体就认为完成了传感器标定，当前也不以鼠标任意拖拽作为正式装配方式。

### 4.2 农机具

1. 在同一装备目录选择当前车型支持的农机具。
2. 安装按钮可用时点击安装，等待自动放到对应挂接位置。
3. 检查车体与机具关系，关闭面板后观察整体外观。
4. 更换机具时，按面板可用操作卸下已有机具，再安装新机具。

不可安装的按钮不可用，不需要修改名称或强行选择。机械臂也是农机具；Car0、Car3 可按适配目录安装机械臂和夹爪。其他机具随车型不同，不能给所有车套用同一目录。

### 4.3 重要安全与能力边界

- 当前机具不作为仿真碰撞体或导航轮廓的一部分；看到机具穿过某些物体不代表已经完成真实机具避障。
- 名称为播种机、耕作机或收割机的模型，不表示已实现相应土壤/作物物理过程。
- 当前装备面板没有喷洒组件，不要将场景任务标签“喷洒”理解为已有可点击喷洒装置。
- 机械臂主要是运动学演示，不提供已经验证的果实抓取、接触力或采摘任务。

## 5. 查看结构与调整支持的参数

### 5.1 爆炸图

1. 点击爆炸图。
2. 观察现有零部件的展开关系。
3. 使用退出/返回入口恢复正常车辆视图。

Car0 采用原有较细分的展开方式，其他车的粒度取决于模型层级。爆炸图只作展示，不把展开状态导出为实际传感器安装位置。

### 5.2 Car0 参数面板

1. 进入 Car0 单车界面，在非 UI 的车身位置双击。
2. 在已有修理/参数面板中选择需要调整的已实现项目。
3. 前后轴距可用滑条、预设或数值输入，当前允许范围为 0.42～0.60 m。
4. 例如输入 `0.50`，检查当前显示，按该面板确认操作完成。
5. 关闭面板，检查车辆显示，再重新导出/启动仿真。

轴距是前后轮中心的纵向距离，不是左右轮距。非法格式、过多小数或越界值应按提示修正。不要假设其他车辆也具有相同修理面板，或配置文件里的所有字段都能在 App 中编辑。

参数变化后，旧仿真结果和配置 SHA 不再自动代表新配置通过。

## 6. 选择内置场景

1. 在单车界面进入启动仿真的配置流程。
2. 打开“01 作业场景”。
3. 根据车辆尺寸和需求选择场景卡片。
4. 在底部确认当前场景名称。
5. 进入“02 算法配置”或点击“选择算法”。

内置有苹果园、玉米试验田、温室行间、农场运输区、番茄温室、草莓种植区、葡萄园、蔬菜试验田和宽地头机具运输区。

选场景时注意大农机的宽度和转弯半径。场景卡片存在不代表所有车都适用；当前候选关系、排除组合和定位限制见[配置附录](14_catalog_reference.md)。

## 7. 导入自己的扫描场景

### 7.1 准备文件

准备当前流程支持的 ZIP，其中应含匹配的 LCC2 索引、高斯资源和碰撞网格。不要仅把任意 PLY、STP、FBX 或高斯文件改扩展名当成支持格式。

保留原始 ZIP，准备足够磁盘空间。转换可能同时保留原始和中间结果，所需空间不等于压缩包大小。耗时受数据规模和机器性能影响。

### 7.2 导入步骤

1. 在作业场景页点击“导入场景”。
2. 输入 1～48 字符的场景名称，不使用换行等控制字符。
3. 点击“选择 ZIP”，在文件选择器中选择对应文件。
4. 检查显示的文件路径，点击“导入”。
5. 等待进度和阶段提示，不在转换中反复提交。
6. 成功后返回场景页，找到标为“用户导入”的卡片并选中。

导入成功才加入场景目录和 AI 上下文。失败时查看错误原因，修正文件/空间/环境后重新操作。取消不会把未完成结果当成可用场景。

### 7.3 首次使用新场景

先用合适的小型车和已知配方检查地图、出生点、虚拟相机/雷达和定位，再尝试长路线。不要根据名称直接断言道路宽度或真实 GNSS 条件。

导入场景不自动继承内置场景的全程通过标签。新场景上推荐了方案，也仍需用户实际验证。

## 8. 删除导入场景

1. 先停止使用该场景的受管仿真，等待停止成功。
2. 打开场景页，找到用户导入卡片右上角 ×。
3. 阅读确认框中的名称和缓存说明。
4. 不删除时点“取消”；确认删除时点“删除”。
5. 等待卡片刷新，再选择其他场景。

删除目录项与转换缓存，不删除原始 ZIP；共享缓存要等最后一个引用删除时才清理。内置场景不能通过该入口删除。

删除后若原场景曾被选中，需要重新选择。AI 的旧方案可能因目录版本变化失效，应重新提问，不能强行应用已删除场景。

## 9. 选择算法

在“02 算法配置”依次选择：

1. 几何感知：STVL 或 Voxel。
2. 视觉感知：关闭，或额外检测、实例分割、姿态估计。
3. 定位：FAST-LIVO2+RTK、FAST-LIO2、NavSat ESKF、KISS-ICP。
4. 规划：Smac Hybrid-A*、NavFn、Theta*、Smac2D、直连。
5. 控制：MPPI、RPP 或 DWB。

检查右侧“当前运行方案”，确保不是“未选择”。关闭额外视觉感知不会关闭 FAST-LIVO2 需要的定位相机。

### 9.1 推荐的选择原则

- 优先采用当前车型/场景的已验证配方，不从选项数量推断任意组合都可用。
- 宽地头统一采用 NavSat；葡萄园 Car3/4/6、玉米田 Car4 等按专用规则处理。
- 需要阿克曼运动学约束时优先选择合适的 Smac Hybrid-A* 配方，不能把二维最短路或直连当成同等曲率保证。
- 机具特别宽或车型特别大时，应先判断场景是否适合，而不是仅调控制器让车强行通过。
- 手工菜单“能选”不等于本地目录推荐或全程已验证，仍应遵循附录。

## 10. 启动仿真与确认就绪

### 10.1 提交启动

1. 确认基础传感器完整，安装动画结束。
2. 确认所选车辆、机具、场景和五组算法。
3. 在配置页点击“启动仿真”。
4. 等待导出、ROS 配置生成与编译准备。
5. 等待 Gazebo/RViz 出现，查看地图和模型。

第一次使用必须已经安装依赖并完成初始构建。软件内的增量编译不是安装 Unity/ROS/模型的替代方案。

### 10.2 不要把派发成功当作导航就绪

出现 PID、导出成功或启动任务已提交，只表示前序操作成功。继续检查：

- 地图和车辆是否显示，车是否在合理位置。
- 传感器消息是否在更新，定位是否稳定。
- Nav2 节点是否已进入可用状态。
- 日志是否有构建失败、TF、时间或输入错误。

默认车辆等待目标，不会仅因窗口打开而自动跑路线。当前仿真提供其配置要求的初始化流程，不应照搬真实车辆的操作命令或盲目重复点击初始位姿。

### 10.3 启动失败

不要连续点击启动。先查看最近日志：

```bash
tail -n 100 ~/.local/state/agribot-unity-sim/latest.log
cat ~/.local/state/agribot-unity-sim/status
```

如果设置了 `XDG_STATE_HOME`，目录相应改变。修正缺依赖、路径、模型或算法问题后再启动。

## 11. 在 RViz 设置单目标

1. 确认 Navigation 2 面板存在，车辆定位和地图正常。
2. 使用 Nav2 Goal 工具，在可通行区域点击并拖动方向。
3. 在普通单目标模式下，目标会提交执行。
4. 观察全局路径、局部障碍和车辆运动。
5. 到点后观察任务完成状态和车辆停止。

目标不能放在障碍物、场景外或无法掉头的位置。拖动方向用于路径姿态，终点停止仍按位置容差，不要求最终朝向完全一致。

例如某配置轴距为 1.20 m，则最终位置容差为 0.60 m；这是说明公式的例子，不是所有车固定参数。目标对应车辆参考坐标，不是车头外壳某个点。

## 12. 设置多个连续经停点

1. 在 Navigation 2 面板进入 Waypoint/Nav Through Poses 模式。
2. 用 Nav2 Goal 按顺序设置每个位置和方向。
3. 检查路径是否符合通道、车宽和转弯要求。
4. 点击 Start Nav Through Poses，提交连续任务。
5. 观察顺序通过与最终停止。

不要把 Start Waypoint Following 与连续 through-poses 混为同一工作流。车辆是否连续运动仍取决于路径、障碍、曲率和控制状态；不能承诺所有尖角点都不停通过。

默认不周期重规划全局路径，但初始、目标更新或失败恢复仍可再次规划；局部控制继续更新。某些反馈计数在非周期规划下可能不逐点刷新，应结合实际路线、任务结果和运动状态判断。

需要取消时使用当前 Nav2 面板的取消操作，确认任务结束和速度停止。清掉显示对象不是取消后端导航。

## 13. 查看相机和额外视觉 AI

- 普通相机显示话题为 `/camera/rgb/image_raw`。
- 选择额外视觉算法后，叠加显示使用 `/vision/annotated_image`。
- RViz 中检查相应 Image 显示是否启用、话题和 QoS 是否合适。

实例分割可包含掩膜、框和标签，显示取决于模型结果；画面中无识别目标不自动代表算法未运行。检测、分割与姿态模型不同，不能仅切换话题就把检测变成分割。

No Image 时先检查消息和渲染，不先怀疑镜头盖或真实相机。本流程使用 Gazebo 虚拟相机。没有图形窗口不代表图像生成不需要 GL。

额外视觉模块不接管导航，不承诺农作物识别精度或语义避障。

## 14. 使用连续 AI 助手

### 14.1 对话

1. 点击 AI 助手，打开对话面板。
2. 输入问题，中文输入法完成候选确认后再发送。
3. 回车发送，Shift+回车换行，也可点“发送”。
4. 等待回答或澄清，不重复提交同一句。

示例：

- “现在有哪些履带车？分别适合哪些场景？”
- “在葡萄园选一个小型履带车，带机械臂，优先稳定定位。”
- “保留当前车辆和机具，只把控制器换成 RPP，说明限制。”
- “使用我刚导入的场景，先推荐一个小车验证方案。”

助手知道的是文字目录和界面状态，不是当前三维画面、点云或定位精度。界面“正在思考…”只是等待文字；当前模型请求的思考模式是关闭的。

### 14.2 应用方案

1. 阅读回答和卡片中的车型、机具、场景、算法及条件。
2. 装配方案点“选择这套装配”，仅算法方案点“采用这套算法”。
3. 等待本地版本复核和配置应用。
4. 回到实际界面核对选择与装备。
5. 确认后再单独点击“启动仿真”。

卡片应用失败时按提示重新推荐，尤其在修改装配、删除场景或配置更新之后。不要将 AI 的推荐文字当成已经执行了运动命令。

### 14.3 上下文与新对话

本次运行内关闭面板或切换页面会保留会话。新对话清空聊天、备忘和旧场景指代，但保留当前实际装配和运行任务。软件退出重开不自动恢复旧对话和装配。

历史记录保存在本机 Unity 用户数据目录，不因新对话自动全部删除。模型使用近期消息和备忘，不保证无限记住所有原文。

场景目录通过只读 list_scenes 查询；版本不变时复用，导入/删除/更新或新会话后重新核实。没有 AI 自动导入、自动启动或任意文件执行功能。

### 14.4 隐私与网络

使用在线模型时，输入文字和相关界面状态会发送到所配置接口。不要在对话中填入密码或密钥。Key 放环境变量或私人配置，不写入仓库。没有 AI 网络时可继续手动配置和仿真。

## 15. 停止仿真与导出

### 15.1 正确停止

1. 需要时先在 Nav2 取消当前任务。
2. 回 Unity 点击“停止仿真”。
3. 等待“仿真已停止”等成功提示。
4. 再切换车辆、场景、参数或退出软件。

仅关 RViz 窗口、返回车库或关闭助手，都不等于所有仿真节点已经结束。停止过程处理本应用的受管会话，不应影响其他项目。

### 15.2 导出配置

1. 确认仿真已停止，导出按钮当前可用。
2. 点击“导出真机配置”。
3. 等待结果，按提示查看输出目录。
4. 保留 JSON、参数和清单，注明具体车辆/机具/场景与版本。

不同车型和接口可能得到模板、草案或完整部署包，不能统称为已标定真机配置。原 Car0 含固件部署包需要额外有效固件输入；本仓库没有附带固件工程。缺少该输入时应明确失败，不属于仿真启动失败。

导出不自动烧录，也不授权外部真实车辆运动。外部接收系统不在本手册范围。

## 16. 文件和日志在哪里

| 内容 | 位置/查找方式 |
| --- | --- |
| Unity 构建 | 默认本仓库 `dist/unity/` |

## 17. 两个完整操作示例

### 示例 A：Car0 苹果园基础导航

1. 打开软件，选择 Car0。
2. 安装雷达、相机、IMU 和卫星定位组件；机具先不安装，或使用当前已适配机械臂。
3. 选择苹果园。
4. 选择 STVL、关闭额外视觉、FAST-LIVO2+RTK、Smac Hybrid-A*、MPPI。
5. 启动仿真，等待地图、定位和导航就绪。
6. 在 RViz 选一个通道内可达的近目标，观察执行与停止。
7. 点击停止仿真，再决定是否导出或调整。

该示例说明操作路径，不代替本机完整资源检查或任意目标可达性验证。

### 示例 B：宽地头的大型农机

1. 从当前目录选择适合宽地头的车辆及机具，检查净空。
2. 选择宽地头机具运输区。
3. 定位使用 NavSat，规划和控制按该车既有配方选择。
4. 启动后在开阔区域设置宽裕转弯目标，不在近处强迫小半径掉头。
5. 观察结果，完成后停止。

模拟 GNSS 正常不表示真实场地卫星信号相同。不要把这个示例用于室内真车 NavSat 验收。

## 18. 常见问题

| 问题 | 处理 |
| --- | --- |
| 启动按钮灰色 | 检查场景和五组组件、导入/删除是否忙、装备/动画是否完成 |
| 点击后车没动 | 默认等待 RViz 目标；再查导航就绪、路径和定位，不以窗口打开就应移动 |
| 规划不出路线 | 检查目标净空、地图边界、车体尺寸/最小转弯半径及所选规划器 |
| 大车绕圈或转不过去 | 放宽目标距离和转弯空间，先判断场景适用性，不缩小车体轮廓强行通过 |
| 到点附近就停 | 当前最终位置容差为半轴距，终点方向不作为停车条件 |
| 又生成一条路径 | 可能是目标更新或失败恢复；无周期重规划不等于任何情况下都不再规划 |
| 相机 No Image | 查图像消息、显示话题/QoS、GL 环境、视觉环境与权重 |
| 机具穿障碍 | 当前机具不参与碰撞和导航外廓，不能当作真实安全效果 |
| 导入失败 | 查 ZIP 格式、索引/资源、磁盘空间、权限和本次日志 |
| 删除后 AI 旧方案不能用 | 这是版本复核，应重新询问和选择场景 |
| AI 报格式/适配错误 | 当前结构或约束未通过；简化需求/澄清，不通过反复点击绕过 |
| AI 没有 Key | 配置本机凭据；或先使用手动工作流 |
| 导出含固件包失败 | 核对是否准备外部固件及该接口前提，不误认为模型/导航失败 |
| 克隆后完整车库无法构建 | 执行 doctor --unity，先补齐资源；源码测试通过不代表模型已齐 |

更多排障见[运行与排障](08_operations.md)。反馈问题时提供具体车型、机具、场景、五组算法、操作顺序、提示和日志，不只说“不能运行”。

## 19. 用户自查清单

以下是建议检查项，不是已经完成的测试报告：

- 正确选中车型，安装的组件与画面一致。
- 场景和五组算法明确，不把旧会话状态当成本次选择。
- 修改参数后重新导出。
- 地图、定位、传感器和导航就绪后再给目标。
- 经停点位于可达区域，适合车宽和转弯半径。
- 额外视觉只作独立显示，不误认为接管避障。
- 任务结束或切换配置前点击停止，并等待成功。
- 导出配置有明确版本，未将名义草案当作真实标定结果。
- 保留原始扫描、用户导出和必要日志。
