# 独立复现与交付验收

## 目标与范围

从本仓库获取代码和Git LFS资源，在另一台受支持的电脑上重建与当前来源应用一致的Unity农机配置软件和配套ROS/Gazebo仿真，不依赖开发者的原工作区、模型缓存、私有服务器或用户目录。

范围包含10辆农机、57个装配预设、传感器/农具安装、爆炸图、车库与配置交互、五组算法选项、9个内置场景、仿真启动/停止、RViz目标/经停点、离线真机配置导出、连续AI助手、中文输入与快捷键、用户扫描场景导入/删除。

用户手工导入的“自动化所园区”数据明确不发布；新克隆不应读取开发者已有的导入目录。导入功能及所需渲染器源代码保留，使用者可以自行导入自己的数据。

农机控制台、Android应用、6750独立上位机和在线烧录不属于本产品。`resources/deployment/`只提供原Unity导出按钮使用的既有离线文件，不代表新增这些软件或通过实板验收。

## 环境前提

- Ubuntu 22.04 x86_64、ROS 2 Humble、Gazebo Classic 11、可用桌面和OpenGL图形驱动。
- 建议32GB内存及充足SSD空间；源代码、LFS资源、Unity导入缓存、ROS和应用构建会同时占用空间。
- 源码构建使用Unity6000.0.26f1、Linux Build Support (Mono)和使用者自己的有效许可证。Unity Editor不是本仓库可重新分发的组件。
- AI助手调用官方DeepSeek HTTPS接口，需要使用者自己的Key和网络。Key不编入应用，缺少Key不影响手动装配与仿真。
- 视觉AI权重已提供，CPU和CUDA运行环境在本机安装。硬件不同会影响帧率和仿真速度；不会因此换成不同的定位、规划或控制算法。

## 完整性与安装

```bash
git clone https://github.com/Guanzhen-C/agribot_report.git
cd agribot_report
git lfs install --local
git lfs pull
python3 tools/doctor.py --unity --hashes
bash scripts/bootstrap.sh
python3 tools/configure_llm.py
bash scripts/run_unity.sh
```

需先安装ROS Humble Desktop。`bootstrap.sh`默认安装系统依赖、构建ROS并创建本仓库专用视觉环境；如果仓库含匹配的`prebuilt/manifest.json`，会校验并安装与源码匹配的Linux程序，无需在运行电脑安装Unity Editor。源码开发者可指定`--build-unity`，此时需要自己的Unity许可证。

已安装系统依赖时可使用 `--skip-system`。`--skip-vision`或`--skip-unity-build`只用于分阶段开发，不能把跳过的功能写成已经完成安装。直接安装预编译程序可运行`bash scripts/install_app.sh`；程序包通过SHA-256和运行源码/资源指纹双重校验，不允许用旧程序冒充改过的源码。

发布用的源码构建先提交运行源码/资源，再执行`bash scripts/build_unity.sh`。脚本在Unity构建前后核对干净Git输入并写入构建记录；`tools/package_app.py`只接受记录与当前输入一致的程序，不会事后给旧程序补写版本信息。开发中的未提交修改仍可在Unity Editor内运行和构建，但不能据此发布通过版本指纹校验的预编译包。

## 目录隔离

`scripts/env.sh`从自身位置推导ROS工作区，不假设用户名、固定IP或`~/agribot_ws`。用户导入场景、仿真状态、AI配置和视觉环境默认写入被忽略的 `.local/`。编辑器仍使用自身的许可配置目录，运行程序使用独立应用数据目录。

构建后的启动脚本使用相对仓库路径及相对可执行文件路径。移动整份仓库时不应继续访问旧构建目录；只复制可执行文件而不携带其配套源工作区，不是本软件的完整部署。

Car0随仓库提供当前已审核的完整车库Prefab，普通构建直接使用它，不重新从旧场景生成不同的序列化副本。构建移植修改和回归测试接口调整记录在来源差异清单中，定位、规划和控制参数不因交付而替换。

交付回归另修复三处独立安装问题：中文字体从Resources显式载入相同Noto字体文件，避免依赖场景载入顺序或系统字体；Car0导出按钮由仿真状态事件刷新，避免车库主面板隐藏后Update停止导致按钮无法恢复；Unity按钮的增量构建与首次安装保持同一仿真包范围，不要求真机海康SDK驱动。这些修改不改变算法及车辆参数。

## 必须验证的内容

1. GitHub远端的新克隆与LFS校验，而非从开发机复制一份资源后假称远端完整。
2. 所有车型/机具资源和缩略图的指纹；Car6高精度显示、履带车和收割机外观与来源一致。
3. 干净工作区中的ROS构建、Unity构建、中文输入原生桥接库和全部运行依赖。
4. 车库、装备、场景、算法、AI会话、导入/删除与导出回归。
5. 9个内置场景资源解析、各算法接口和实际默认整车仿真。参数和算法与来源一致，不能以真值里程计替代FAST-LIVO2融合定位来获得更容易通过的结果。
6. 默认阿克曼完整路线及目标/经停点、停止操作；导出文件不得依赖仓库外的本机目录。
7. 视觉AI三种模式真实推理与ROS输出，使用所提供的相同权重，不用占位画面代替。
8. 不包含用户园区数据、个人凭据、专利/软著材料或农机控制台。

测试、指纹、构建日志和运行结果只是对应范围的证据，不把源码测试或启动检查扩大解释为所有车型在所有场景的全程自动行驶验收。
