# 系统概览

## 目标与流程

软件围绕“配置车辆与传感器 -> 选择场景和算法 -> 仿真观察 -> 导出真机配置 -> 控制台加载与真机检查 -> 执行导航/采集”组织。配置通过统一 JSON 契约传递，避免 Unity、Gazebo、定位和导航各自维护一套尺寸。

这不是仅有一个可执行文件的系统。不同职责放在不同计算设备上：

| 位置 | 软件 | 职责 |
| --- | --- | --- |
| PC 工作站 | Unity Linux 应用 | 车库、装备安装、场景、算法、AI 问答、启动/停止仿真、导出 |
| PC 工作站 | ROS 2 + Gazebo Classic + RViz | 动力学、虚拟传感器、定位、路径、控制、可视化 |
| RDK X5 等车端 | ROS 2 驱动/算法/网关 | 真实数据、定位、规划控制、CAN、采集、HTTP 状态 |
| 手机/平板/浏览器 | 农机控制台前端 | 地图、车辆位置、路径、状态、任务和采集控制 |
| 可选 HPM6750 | FieldGate VCU 固件 | 指定车辆协议的 CAN 桥接、状态与诊断 |
| 可选服务器 | 语义规划服务/Neo4j/模型接口 | 独立于车端闭环的自然语言语义任务 |

## 当前应用功能

Unity：十车型目录 Car0 至 Car9；阿克曼、差速/履带运动学；固定默认传感器安装位置；按适配关系安装机具；场景选择和扫描场景导入/删除；五组组件选择；AI 连续对话和可点击方案；配置与网格导出；受管仿真启动停止；离线真机包导出。

控制台：连接车端 HTTP 网关；二维地图/位姿/轨迹/规划；初始位姿、单目标与连续经停点；导航取消；运行任务管理；传感器有无数据；采集开始停止；配置包导入与恢复默认；底盘/电池/可选 VCU 状态。具体是否有数据由对应驱动和设备在线状态决定，不伪造在线。

## 不包含的承诺

不自动标定任意新车；不自动生成安全 CAN 协议；不保证任何模型/场景/算法组合都可闭环；不以自然语言直接驱动底盘；不提供公网远程控车安全认证；不模拟真实土壤耕作产量。仿真已有机具主要用于安装和运输展示。

## 源码关系

`unity/` 来自独立 Unity stage 分支，`ros2_ws/` 来自 ROS 主工程当前工作树，`firmware/` 来自 HPM6750 项目。原始提交号见清单，所有交付修正只针对新仓库，不把开发机缓存和原 Git 历史混入交付。
