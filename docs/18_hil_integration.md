## 传感器装配与启动条件

所有10辆车都必须安装雷达、RTK、相机、IMU四个模块，且安装动画完成后，才允许启动普通仿真或HIL。RTK模块包含左右两根天线。卸下任一模块后，点击启动会提示缺失的装备，直接调用按钮事件也不能绕过检查。普通仿真还需选择场景和完整算法；HIL另需满足已开放的车辆、农具、场景和算法组合。

车库和普通导出统一使用HIL同款短杆双天线，不保留旧的高竖架。57个农机装配预设保留原天线的前后、左右位置和支撑面，只替换RTK网格并降低天线中心；其他车体与农具几何不变。Car3的雷达、相机、IMU和双天线位置使用已验证HIL场景中的相对`base_link`坐标。对应资源与安装表在`unity/Assets/AgribotConfig/Resources/HilSensors`，更新工具为`tools/hil/export_unity_sensors.py`和`tools/hil/update_farm_rtk_assets.py`。

Car0的双天线与HIL统一前移至上顶板两侧、原果盒前方，相对`base_link`为`[0.12, 0.15, 0.2348]`（左主）及`[0.12, -0.15, 0.2348]`（右副），短杆脚落在`z=0.1348`的顶板。果盒、支架、落果位、路线和导航参数保持原样。`tools/hil/sync_ackermann_rtk.py`核对Unity与ROS安装表后同步HIL SDF、URDF、MoveIt模型、RTK杆臂、地理参考和资源哈希。安装位置变化后须同步PC和X5的独立HIL场景配置，不能仅更换Gazebo可视网格；不修改真车标定或固件协议。此前全程测试记录对应旧安装布局，新布局的静态一致性测试不替代新的全程HIL验证。

## 自动烧录顺序

每次点击启动，即使连续两次选择同一工况，也完整执行一次烧录：

1. 校验工况、场景包、ELF哈希及烧录器/CAN身份，检查X5独立运行环境。
2. 停止本应用上一轮任务，撤销行走和作业授权，释放HIL通信。普通受管仿真也先停止。
3. 比较X5真车工作区指纹。
4. 用绑定的CMSIS-DAP烧录器下载对应ELF，弹出烧录进度对话框，必须收到Programming Finished和Verified OK，再复位运行。不对整片Flash擦除，不覆盖末尾配置区。进度按OpenOCD实际输出的连接、写入、校验、复位阶段推进，不是假定耗时或Flash字节百分比；仅在进程成功退出且校验标志完整时显示完成。
5. Car0使用1Mbps，并显式沿用原`prepare_can.sh`的87.5%采样点、1024帧发送队列，配置后读回核验；不能退回内核默认75%/10帧。Car3和Car4保留250kbps配置。只配置绑定的PC台架CAN盒，每次启动均在上一轮HIL停止、固件校验结束后，对绑定的PC `can0`执行down/配置/up，清理可能堵住的发送与回显队列，不再仅凭ERROR-ACTIVE和相同波特率复用接口。X5仅准备专用vcan73/vcan74，不修改其真实物理CAN配置。
6. 启动PC场景和X5算法，等待新鲜硬件反馈、推进的仿真时钟、定位与Nav2生命周期就绪。
7. 再核对真车指纹，然后授权并执行默认任务。尚未完成就绪检查时不放行行走。

任何失败都会停止HIL并撤销授权，不能假装烧录成功或回退到纯软件控制。烧录中点击停止只提交停止标志，等写入和校验完成后处理，不能中断Flash写入。该功能不负责给真车烧录或改动真车CAN协议。

阿克曼CAN桥接将短暂发送拥塞（ENOBUFS/EAGAIN）与断线、非法报文区分：拥塞时输出零速度，反馈重试限制为20Hz；三个原生反馈分片之间按既有有限链路测试留3毫秒间隔，避免USB突发。只有完整三帧反馈成功发送后才清除拥塞故障，并丢弃旧目标，等待新的原生CAN命令后恢复。断线、协议及限值错误不会自动清除。首次启动就绪检查还要求完整反馈发送时间新鲜。原底盘CAN报文、速度限制、路径和MPPI参数不变。

2026-11-12此项修复的物理链路检查使用`can_probe --rounds 600 --period 0.05 --timeout 55`：X5发送600帧零速原生命令，PC全部接收并回复1800帧停车反馈，X5逐字节及顺序检查1800帧全部通过，发送队列无新增积压/丢弃。该检查经过当前6750固件，不绕过CAN，不包含整条导航或采摘任务。原始未节流发送测试的分片丢失记录另行保留，没有用通过结果覆盖。

随后用户启动的整机任务`20261112T063605_4ff80674`仍出现CAN发送队列持续积压，采摘尚未开始；不能将上述零速通过视为整机问题已根治。对比原来跑通的初始化脚本，确认新集成入口遗漏87.5%采样点和1024帧队列。已恢复两项并增加实际接口读回及回归测试，整机行走和采摘须另行复跑验证。

恢复原参数后的`20261112T065448_c1d77242`仍失败：实际TX计数停止，命令帧仍在接收，发送队列固定积压222帧；没有到达采摘位，未发生选果或抓取。该记录保留为失败，不将增大队列视作根治。新增受控发送通道恢复：仅在ENOBUFS/EAGAIN持续、真实发送计数不再增长且USB身份/CAN状态仍通过检查时，桥接先输出零速度并清掉旧目标，关闭旧socket，再调用绑定台架CAN盒的权限助手重建接口和socket。之后仍需新的原生命令及完整反馈，不能绕过CAN驱动车辆。每次任务最多实际重建三次，尝试间隔至少5秒；身份、物理错误状态、重建失败或超限均保持停车。该措施是针对已观察到的发送通道停滞的恢复机制，不证明适配器固件层根因已经消除。

## 首次准备

普通仿真安装流程不受影响。HIL还需在PC配置免密SSH密钥和可信X5主机指纹及HPM OpenOCD。必需的6份HPM板级配置已按BSD-3-Clause原样收录在`resources/hil/openocd`，启动前逐份校验哈希，不需要另复制整套SDK。不要在Git中保存密码或私钥。

相机参与定位的Car0/Car3还要求两端安装压缩图像传输插件。首次在笔记本准备HIL时，可运行以下命令补齐相机编码和机械臂消息依赖；不执行发行版升级。基础安装脚本现已包含压缩图像插件，HIL预检也会在烧录前检查该插件，避免缺图像时一直等待定位：

```bash
sudo apt-get install --no-install-recommends --no-upgrade \
  ros-humble-compressed-image-transport ros-humble-moveit-msgs
```

按`tools/hil/connection.example.json`的字段创建`.local/hil/connection.json`，实际路径必须对应本机安装。烧录器序列号应填经检查的FireDAP序列号。运行前先通过只读工具记录真实运行环境指纹，例如：

```bash
python3 tools/hil/protect_real_runtime.py \
  --host sunrise@192.168.1.102 --identity ~/.ssh/agribot_hil_app_ed25519 \
  --known-hosts ~/.ssh/known_hosts \
  --output .local/hil/protected-real-runtime.json
python3 tools/hil/deploy.py
sudo python3 tools/hil/install_permissions.py --user "$USER" --probe-serial <已核实的序列号>
```

部署工具仅将列明的HIL源码、场景和固定外部依赖传入专用目录；不上传Unity资产库、不复制真车工作区。PC编译Gazebo插件及附着服务，X5编译Python叠加包、独立FAST-LIVO2和两个ISOBUS端点。AgIsoStack++与IFRA LinkAttacher固定提交并校验，X5无需自行访问GitHub。FAST-LIVO2必须独立编译，因为上游二进制固化的ROOT_DIR会将调试日志写回原源码目录；其他已有ROS依赖仅作只读下层。不宣称在没有ROS依赖的新系统上开箱即用。

权限准备只给绑定烧录器的USB/HID接口授予plugdev访问，并只允许操作已绑定PC CAN盒的250kbps和1Mbps两个命令，不授予任意root命令或系统级网络能力。

## 操作与日志

在车库选车，打开装备面板安装四个基础传感器和适配机具，点击顶部原有“启动仿真”进入设置，选择相应场景及完整算法，拖拉机再选择CVT或动力换挡，点击面板底部“启动HIL仿真”。观察烧录进度对话框、启动、定位就绪和任务状态；结束或中断使用原“停止仿真”入口。烧录对话框的“取消启动”仅提交取消请求，写入及校验结束后再清理，不中断Flash写入。任务完成后可保留Gazebo查看效果，但行走及作业已撤销授权；切换到普通仿真前先停止HIL。

命令行诊断接口对应同一启动链路：

```bash
python3 tools/hil/cli.py start --profile tractor_cvt \
  --algorithm stvl_off_navsat_smac_hybrid_mppi --sensors Radar RTK Camera Imu
python3 tools/hil/cli.py status
python3 tools/hil/cli.py stop
```

PC每次运行保存于`.local/hil/runs/<run_id>`，含步骤、烧录、操作、真车指纹核对和任务结果。X5日志为专用目录`runs/<run_id>`，保留CAN和ISOBUS原始记录。失败记录不覆盖，不能只保留成功截图。

CLI要求显式给出算法及传感器清单；这属于诊断调用方的装配声明，不是远程检测Unity模型。日常从Unity界面启动时，会同时检查实际装配状态和模型是否可见。CLI不补选算法，缺少声明时在接触硬件前拒绝请求。
