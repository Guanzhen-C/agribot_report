# 农机配置与算法仿真软件详细功能说明

文档范围：当前 Unity 桌面软件及配套 ROS 2、Gazebo、RViz 仿真。本文用于设计说明和使用文档编写，不是软著申请材料或第三方检测结论。

## 1. 产品定位

软件提供可视化农机配置与算法验证工作流。用户在三维车库中选择车辆，安装传感器和农机具，选择作业场景及算法组件，由软件导出一致的车辆配置并启动仿真，随后在 RViz 中指定导航任务、观察结果，最后停止仿真并保存配置。

产品主流程：

```text
启动软件 -> 车库选车 -> 配置/装配 -> 选择场景 -> 选择算法
        -> 导出与准备 -> Gazebo/RViz -> 指定目标/经停点
        -> 观察运行 -> 停止 -> 导出配置或调整后重试
```

AI 助手可在上述过程中持续对话并推荐方案，但不代替用户启动仿真，也不直接控制车辆。

### 1.1 包含与不包含

| 范围 | 内容 |
| --- | --- |
| 包含 | Unity 车库、装配、显示与参数操作、场景管理、算法选择、AI 助手、配置导出、受管仿真、RViz 操作 |
| 依赖 | Unity 运行环境、ROS 2/Gazebo/RViz、所选算法库、必要模型和可选在线模型接口 |
| 不包含 | 农机控制台、Android/网页控车、控制台 HTTP 网关、固件工程、真实车辆联调、独立离线建图服务 |

共享源码包可能含真机算法实现；它们为仿真提供定位或公共库，不表示软件另有真实控车界面。

### 1.2 功能存在与交付完整性的区别

功能代码及完整10车型、57个装配预设资源已随仓库交付，模型提供者已确认分发权限。完整性核验、构建与实际运行仍需分别验证，不能把“文件已存在”当成全流程成功。支持平台、外部工具链和实际验证范围见[资源说明](09_resources_and_licenses.md)、[验证记录](10_validation.md)及[独立复现说明](15_reproducibility.md)。用户导入的扫描场景属于私人本机数据，不随仓库发布。

## 3. 车库与三维配置

### F01 初始化

- 新应用进程从未选车辆、未安装装备、未选场景和算法的状态开始，不自动恢复上次会话。
- 本次运行中跨页面保留实际选择，避免每次打开面板都重新配置。
- 已导入场景库和已导出的文件是磁盘数据，不因新对话或应用重启自动删除。
- “新对话”仅重置 AI 会话，不重置整套车辆装配，也不自动停止已有仿真。

### F02 车型选择

车库目录包含 Car0 至 Car9，涵盖阿克曼小车、轮式拖拉机、履带小车、骑乘式割草机和履带式联合收割机主机。准确名称、运动学和预设 ID 见[配置附录](14_catalog_reference.md)。

选择车辆后进入单车界面，使用对应模型、装备适配及相机目标。返回车库用于重新选车；软件不再为 Car0 额外保留一套与其他车功能重叠的“回到开始”入口。

车型外观大小与物理参数是不同概念。导航使用配置中的米制尺寸、轮心、轴距、轮半径等，不将车库画面缩放直接当作动力学参数。

### F03 三维观察

- 在非 UI 区域按住鼠标左键拖动，围绕当前车辆观察。
- 滚轮改变观察距离，使用平滑和范围限制。
- 指针位于有效 UI 图形上时阻止相机误响应，避免拖滑条时车辆视角跟着转动。
- 装备/修理等面板可以临时锁定观察视角，关闭后恢复；不把相机怼近当成参数编辑要求。
- 代码含触控输入分支，但本交付以 Linux 桌面应用为支持基线，不据此承诺手机/平板发行版。

### F04 传感器装卸

基础装备分为三维激光雷达、相机、IMU、卫星定位组件。卫星定位组件可对应主副天线，不能将一项装备与一个坐标锚点简单等同。

用户选择装备后查看名称和预览，点击安装或卸下。软件更新当前装备状态、三维模型及 AI 操作上下文。安装位置使用车型适配的固定锚点，不提供当前运行版中的任意鼠标拖拽标定。

安装动画未完成、必要装备缺失或不适配时，导出/启动可能被拒绝。不适配机具的安装按钮不可用；装备详情不再使用大段溢出的说明文字。

### F05 农机具装卸

机械臂归入农机具，与其他农机具放在同一装备体系。目录还包括犁、耙、中耕/开沟类机具、播种类机具、拖车、前置割草刀杆和联合收割机割台等，具体以附录为准。

- 仅在有对应装配绑定的车型上安装，自动放在预设挂接位置。
- Car0、Car3 的机械臂与夹爪用于运动学演示，不代表接触式采摘或机械臂扫掠避障已经实现。
- 部分机具名称带有真实农艺用途，但当前仿真主要验证装配和行驶运输，不实现土壤、作物切割、播种、喷洒和产量过程。
- 当前运行时机具及机械臂不参与导航轮廓和碰撞。车辆本体、车轮接地及环境障碍仍保留。
- 不把历史代码里存在的喷洒支持说成当前装备面板已经提供喷洒组件。

### F06 参数操作

Car0 通过双击车身打开已有修理面板；未实现该面板的车型不增加占位提示。参数功能以实际面板为准，不将配置文件中的所有字段描述为都可在界面编辑。

当前 Car0 前后轴距面板支持滑条、预设按钮和数值输入，范围 0.42～0.60 m。数值按四轮中心测量基准解释，不是左右轮距。软件校验格式和范围；无效输入提示修正，不静默当成合法参数。

参数改变后需要重新导出并重新准备仿真。旧配置指纹下的通过记录不能直接证明修改后参数的效果。

### F07 爆炸图

通过“爆炸图”观察现有模型零部件结构，可退出并恢复正常展示。Car0 保留原有较细分的展开实现；其他车型的拆分粒度受原模型层级限制，不能承诺任意导入模型都自动获得相同细分程度。

爆炸图是展示状态，不把散开的零件位置作为物理装配的新外参，也不等于修改真实车体结构。

## 4. 场景管理

### F08 内置场景

配置页包含“01 作业场景”和“02 算法配置”。内置目录包括苹果园、玉米试验田、温室行间、农场运输区、番茄温室、草莓种植区、葡萄园、蔬菜试验田、宽地头机具运输区。

场景卡片提供名称、预览和任务标签。标签用于目录描述，不证明物理农艺作业已实现。不同车型净空与最小转弯半径不同，场景可见不等于对所有车型适用。

### F09 用户扫描场景导入

入口为“导入场景”，输入名称并选择支持的 ZIP。当前流程要求相应 LCC2 索引、高斯数据和碰撞网格，执行解包、数据验证、转换、地图/出生点等准备后发布到本机场景目录。

软件显示进度和错误，成功才记录“导入完成”事件。支持取消；未完成的转换不冒充可用场景。导入过程有路径、体积、目录和并发保护，不能用任意路径工具代替。

这不是任意 STP 农机、任意高斯格式或任意三维文件的一键兼容接口。导入后仍需验证传感器、地图与通行性。

### F10 删除和缓存

仅用户导入场景卡片有右上角 ×。点击后确认，删除目录项并清理相应转换缓存，共享缓存保留到最后一个引用删除。原始 ZIP 不删除。

删除成功会清除相关当前选择/最近导入引用，刷新卡片和 AI 场景目录版本。运行或准备中拒绝不安全删除；缓存或目录操作失败应显示错误，不假报完成。删除或修改场景后，旧 AI 方案不能绕过版本检查继续应用。

## 5. 算法、导出与运行

### F11 五组算法

| 类别 | 选项 |
| --- | --- |
| 几何感知 | STVL、Nav2 Voxel |
| 视觉感知 | 关闭、AI 目标检测、AI 实例分割、AI 人体姿态估计 |
| 定位 | FAST-LIVO2+RTK、FAST-LIO2、NavSat ESKF、KISS-ICP |
| 规划 | Smac Hybrid-A*、NavFn、Theta*、Smac2D、必经点直连 |
| 控制 | MPPI、RPP、DWB |

五组选择共同构成运行方案。额外视觉选择“关闭”不等于关闭 FAST-LIVO2 的定位相机。

软件和 AI 使用当前车辆、机具、场景配置组织方案。宽地头以及部分车型/场景有 NavSat 专用规则。**接口可选、菜单能选、推荐候选和全程验证通过是四种不同状态。** 手工选择也应遵循已记录的适配规则；二维规划和直连不保证阿克曼曲率或避障能力。

### F12 配置生成

Unity 从当前装配导出车辆 JSON 和网格，由生成器校验后形成 URDF、SDF、参数 YAML 与清单。坐标采用 ROS FLU，米/秒/弧度；Unity 坐标由统一转换器处理。

传感器测量锚点、车体显示网格与碰撞近似分别处理，防止把外壳或装饰包围盒错误用于传感器测量。生成 manifest 和配置 SHA 用于追溯。JSON 存在不表示引用模型都已交付。

### F13 启动与停止

启动顺序为校验装配、导出、导入/生成、编译准备和启动受管会话。脚本管理自己的 PID/会话、锁、状态和日志，准备失败不冒充启动成功。

“启动任务已提交”只证明已派发启动过程，不表示定位、地图和导航已经就绪。用户需要查看日志和 RViz。

正常启动不自动下发目标。替换旧任务或停止时仅处理受管会话，不对共享电脑执行全局 killall。停止后再更换车辆/场景是推荐操作。

### F14 导航任务

RViz 提供官方 Navigation 2 面板和 Nav2 Goal 工具。支持单目标及 NavigateThroughPoses 连续途经任务。用户指定位置和方向，规划器结合地图与车辆约束生成路径，控制器驱动 Gazebo 模型。

最终位置验收使用当前前后轴距一半，不要求最终航向；中间点顺序仍保留。默认无周期性全局重规划，但保留初始规划、目标更新和失败恢复；局部控制与障碍更新继续执行。

已有预设路线仅在显式启用自动路线验证时使用，不把 Car0 的固定点直接套给大尺寸农机。不能承诺任意经停点均可达或任意布局都能不停通过。

### F15 显示

Gazebo 展示场景、车辆、运动及虚拟传感器。RViz 展示二维地图、机器人模型、TF、定位轨迹、规划路径、局部障碍及相机。显示结果与后端任务状态需分别检查，界面不动不一定是算法停止，单有 topic 名称也不证明持续有消息。

无 Gazebo 窗口仍可能需要 GL 环境生成相机图像。实时率和传感器频率应实际测量，不把渲染帧率当作定位性能指标。

### F16 额外视觉

检测、实例分割、姿态估计使用各自模型和权重，输出叠加图 `/vision/annotated_image`，供 RViz 显示。实例分割应按模型标准输出掩膜/框等，不把检测框宣称为精确作物分割。

该模块不直接加入当前规划/控制闭环，不表示已经实现语义避障、病虫害识别或农作物识别精度验收。

### F17 配置交付

停止仿真后使用“导出真机配置”。现有接口按车型提供已验证模板或名义草案，不自动把所有仿真组合转换为可直接执行的真实车辆配置。

原 Car0 含固件部署包接口还需要外部有效固件输入；本仓库不附带该固件工程。导出成功不等于标定、烧录、联调或授权运动成功。外部接收应用不属于本软件。

## 6. AI 助手与上下文

### F18 连续问答和方案

用户可询问车辆/机具/场景，也可要求推荐方案或仅更换算法。响应可以是文字、澄清问题、配置卡片或算法卡片。卡片的“选择这套装配”或“采用这套算法”由用户点击后执行本地应用。

上下文包括当前页面、车辆、装备、场景、算法、近期对话和已发生操作、会话备忘及目录版本。界面操作不作为控制命令执行，也不全部显示成聊天消息。模型没有查看实时图像、点云、运行质量或文件系统的通用权限。

只有一个只读工具 `list_scenes({})`，查询内置/导入分类、数量和当前可用目录。目录版本不变时复用，导入、删除、版本变化或新会话后重新核对。名称不等于自动语义识别。

应用方案前再次校验车辆/场景版本和适配关系；格式错误有界纠正重试，不无限请求，也不放宽约束。模型请求关闭思考模式，但界面可能显示“正在思考…”作为通用等待文字，不能据此判断已开启推理模式。

关闭助手不取消本次对话；跨页面可继续。新对话清空聊天、备忘和相关历史指代，但不擅自改变当前装配或停止仿真。应用重启不恢复旧会话。近期上下文与备忘不保证无限逐字记忆。

在线模型需用户配置凭据和网络。问答与文字状态会发往所配置接口；完整本机历史库、相机和点云不自动上传。

### F19 追溯

- 配置 JSON、生成 manifest、模型和配置 SHA 标识本次输入。
- 受管启动脚本记录准备、构建、运行、停止和失败状态。
- AI 对话/界面事件以 JSONL 存在 Unity 用户数据目录中，不进入 Git。
- 代表试验、人工分组确认与自动全程验收分别记录，不能相互替代。

## 7. 重要限制与非功能

1. 没有真实土壤、作物作业、采摘接触和产量模型。
2. 当前机具不参与路径规划轮廓和碰撞，因此不验证机具净空安全。
3. 不提供任意用户 STP 农机模型自动识别运动学并完成标定的已验证流程。
4. AI 不自动启动仿真或发送目标，不是实时闭环控制器。
5. 模拟 GNSS 可用不证明真实室内或遮挡处能用 NavSat。
6. 选项数量和人工分组确认不等于全部组合实测。
7. 完整车库的资源与实际构建状态以仓库预检和验证记录为准。
