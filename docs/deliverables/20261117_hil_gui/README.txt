控制器HIL五工况界面操作版

需规：V2.2；测试用例与记录表：V1.7；各类10条，共30条。
用户只按原软件流程启动A/B/C/D/E工况、截图，完成后正常停止仿真。
没有新增测试启动页，不需要终端命令、不另启测试任务或故障注入。

Unity原HIL启动成功返回运行编号后自动启动只读记录服务。
采集烧录阶段、实际CAN、传感器、定位/路径、机具与终点数据；到点后
观察原5秒仿真时间，提示人员按原停止按钮，停止后保存完整物理日志。
原USB-CAN日志只在停止时写完，所以不在运行中用不完整日志判通过。

记录在.local/hil/recordings/；配置页“测试记录”打开campaigns目录，
桌面“控制器HIL测试记录”仅为链接，不复制大模型或整库备份。
每轮cases.json、cases.csv和30项测试记录.txt对应实际run_id。
同轮同工况取最后一次尝试，所有之前失败记录保留；下一完整轮/下一天
自动新建，不把历史成功记录混成新结果。五工况无需固定执行先后顺序。

与V2.1的区别见需规“范围变更及不覆盖事项”。本版是正常流程范围修订，
不宣称正常启动已经测过旧版取消烧录、非法参数、断令断链或故障恢复。
旧V2.1需规、原30条历史记录和冻结复测脚本原封保留。
功能离线测试不等于重新完成30条实板；第三方本轮必须实际操作并截图。

files/保存Word、PDF、TXT、判据JSON和对照CSV。
build_materials.py从仓库既有机构表单与当前判据生成两份Word，
需要python-docx。PDF可复用相邻20261117_hil_readable/export_materials.py。
普通测试人员只阅读成品和操作软件，不需要运行这些维护脚本。
