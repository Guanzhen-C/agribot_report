# 农机统一配置导出

该模块把 Unity 场景中的车辆几何与传感器锚点导出为 ROS FLU 配置。

2026-10-19 扩展：同一车库新增 Car9“履带式联合收割机主机”；同一装备面板新增大蒜播种机、灌水覆膜播种机（Car6）、双轴农用拖车（Car7）及谷物收割割台（Car9）。`CarN` 只命名主机，机具分别使用 `GarlicPlanter`、`MulchPlanter`、`FarmTrailer`、`CombineHeader` 等独立名称，不创建机具 Car 编号。仍采用固定自动安装，不兼容车型禁用安装按钮。

Car9 主机默认不带割台；安装割台导出 `harvester_header`，卸下导出 `tracked_harvester`。源 CAD 的小比例几何按明确的 10 倍名义设计比例准备为全尺寸仿真模型：主机约长 11.33 m、宽 4.54 m，割台外宽约 12.72 m。它们不是厂家实测标定尺寸。接触轮、质量、惯性、碰撞、自车过滤、导航轮廓与同一配置同步；传感器保持原物理尺寸，重新放到主机固定安装点。只验证差速近似运输，不模拟收割、割台驱动或原机后轮转向。

大机型扩大现有车库和视角范围，不缩小车辆或机具；长拖车组合保持米制 1:1 比例并斜向停车，卸下恢复裸车位置与视角。没有新增页面或拖拽交互。全部新增配置仅为名义仿真参数，不改已验证真车参数。

当前桌面构建：`~/Builds/AgriculturalCar_Interior_Linux_20261021_tracks`。裸机与带割台分别取景；导出安装坐标不受相机距离影响。车库构建处理移除其静态合批标记，保证运行时扩大的墙体和相机边界一致。旧构建保留备份。

本地扩展车型位于同一个可滚动车库：Car6 为紧凑型轮式拖拉机，Car7 为带驾驶室轮式拖拉机。两车复用既有传感器 CAD，点击安装后使用固定默认位置。凿式犁、圆盘耙、六行开沟机、悬挂式中耕机、林地粉碎机、四行铣土机和机械臂共同位于原装备面板：犁与耙适配 Car6，其余四种后悬挂机具适配 Car7；同一车辆的后方挂接农具互斥安装。机械臂保留阿克曼车与履带车的原安装位。安装、卸载和 ROS 导出使用同一组预设，不提供拖动编辑；原六辆车的默认安装位置保持不变。

不适配当前车型的装备只禁用“安装”按钮，保留名称和预览图，不显示适配说明文字。

装备列表沿用三列滚动布局，超出两行时显示右侧滚动条；可用滚轮或拖动滚动条查看圆盘耙、六行开沟机等后续项目。旧面板关闭了滚动条图形，现已恢复，农具资源和安装位置未因此变更。

1. 运行 `Assets/Scenes/scene1.unity`，选择车辆。
2. 原车 Car0 进入 `scene2`，顶部操作栏提供爆炸图、启动仿真、停止仿真、导出真机配置和装备；独立 `BACK` 返回车辆选择页。
3. 新车 Car1～Car5 在当前场景配置车体和装备，顶部操作栏与原车使用相同的操作和视觉样式。爆炸图的滑块收起后会恢复部件原位。
4. 完成安装动画后点击“启动仿真”，在共用的算法选择窗口中选择组合。使用“停止仿真”关闭本次 ROS 进程。
5. 每辆新车分别导出至 `ConfigExports/unity_car1`～`unity_car5`；原车保留 `ConfigExports/ackermann_current`，互不覆盖。

“启动仿真”使用所选场景的预设路线，苹果园仍保留原有全部 23 点；其他场景使用各自地图和路线。ROS 会等待定位和 Nav2 就绪，生成并验证经过全部规定点的路径后再开始运动；Unity 正常启动不会继承终端的静止检查开关。新增大型拖拉机仅完成指定短程或番茄温室 3 点路线验证，不代表能够通过原小车的全部狭窄路线。

新车的已安装 IMU、雷达、相机和双 RTK 天线总成分别导出为传感器 OBJ/MTL，安装坐标与车体网格分开保存。双天线总成只导出一次，ROS 显示完整传感器外观，不再使用简化占位块。

履带车保留 MPPI、RPP、DWB 三个控制选项。ROS 侧根据车型自动使用差速配置：MPPI 的 DiffDrive、RPP 的差速朝向调整、DWB 的标准差速轨迹生成器。阿克曼车型继续使用原控制配置；不需要在 Unity 中另选运动模型。

坐标约定：Unity 使用 `+Z` 前、`+X` 右、`+Y` 上；导出器统一转换为 ROS FLU，即 `+X` 前、`+Y` 左、`+Z` 上。阿克曼车 `base_link` 位于后轴中心，履带车位于四个虚拟轮心的中心。禁止在导出后手工交换坐标轴。

新车型由当前场景的轮心、网格和传感器安装位置生成名义仿真参数。前后轮可采用不同半径，左右按空间位置识别。Car3 使用差速驱动和四个不可见接地滚轮。Car1～Car5 点击“导出真机配置”后，在 `~/unity_exports/unity_carN_physical_draft/` 得到各自的离线草案，包括车辆JSON、导航几何、传感器安装位姿、运动学及FAST-LIVO2外参文件和SHA-256清单。草案明确标记未经真机标定、不含底盘协议或固件，不能直接导入农机控制台或用于控车。原车Car0的已验证配置导出流程保持不变。

### 履带及轮胎外观导出

Car3 的车库预览和导出使用 `LocalVehicleAppearances/unity_car3` 中经过哈希检查的深灰小履带、灰白滚轮资源。保留原场景的四轮中心、装备节点与传感器导出，独立复制14组滚轮与左右各64段履带，并保留JSON中的显示动画扩展。轮心或轮径改变时必须重新适配，不能静默套用固定外观。Car9的主机与割台资源同样包含完整轮胎、履带段和黄色贴图依赖；JSON原样复制，避免丢失动画字段。Gazebo/RViz中的显示运动读取原驱动轮反馈，不增加碰撞或质量，不等于柔性履带力学。原始FBX和CAD保留，新增派生网格仍为本地忽略资源。

Car3、Car9的主界面缩略图从同一份详情模型生成，不再使用旧履带车图片或旧收割机图片。编辑器菜单“农机配置/刷新履带车型缩略图”生成PNG及来源模型SHA；打包前校验来源，模型改变而未刷新缩略图时拒绝构建。AFM1预览采用纹理平均色显示黄色漆面，ROS导出仍携带完整UV和PNG贴图。

新增阿克曼车型使用 35° 的仿真默认最大转角，并按各自轴距计算最小转弯半径。该值不是厂家或实测数据，实际车辆部署前必须替换为测量值。Car0 的已标定转角不受此默认值影响。

## 可选机械臂

在装备背包中选择“六轴机械臂”（Hand），支持阿克曼车 Car0 和履带车 Car3。安装后沿用作者场景的底座位置，显示六轴与夹爪动作；卸载后不导出机械臂。底座不会改变车辆的 base_link 或传感器标定。

启动仿真时，导出的 `manipulators` 字段带有底座位姿和演示开关；ROS 生成独立 URDF/SDF 运动链及夹爪，不把机械臂重复合并到车体 OBJ。展示机构不模拟真实负载、抓取碰撞或真实机械臂驱动，原有真机控车流程不受影响。

## 固定安装位置

传感器和机械臂使用程序与原始场景中的默认安装位置，仅保留“安装/卸下”。不提供运行时拖动或位置编辑，也不读取旧版 `MountProfiles` 中的位置覆盖文件。导出沿用既有传感器基准与坐标转换。
